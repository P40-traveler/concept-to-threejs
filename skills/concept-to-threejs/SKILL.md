# 从概念图到可探索的 Three.js 场景

## 新建场景

1. **从画面里读出空间。** 查看用户实际给的图，提取轮廓、尺度感、材质、色光、构图和想保留的意象。多图服务于同一世界时说明如何融合。若用户明确要求逐图分别建场景，就分别执行。超现实画面允许重构空间；把刻意违反重力的部分标在布局上，把游览路线做成能从多个角度看懂的三维空间。
2. **亲自写提示词，生成三个布局并选一个。** 用可用的生图工具分别生成三个候选布局图，沿用概念图的美术语言，改变地形、地标关系与游览路径。看过三张实际图片，再按[布局与提示词](references/art-direction.md)中的标准选案。保存图片、对应提示词和简短取舍，用户可回看另两个方案。默认直接选定并继续；用户要求先看方案时在这一站交付。
3. **用灰模确定交界，再生成分区参考。** 用选定布局定下地标、尺度、相机和主要路线，快速渲染灰模，检查进入、靠近、回望三个视角。按能独立建造且能拼接的范围划区。结合选案和灰模，为每区写专用提示词，生成并检查真实建模参考图。保留每张图片与文字、区域的对应关系。
4. **分发建模并合场。** 按[分区建模交接](references/model-handoff.md)给每个独立子 agent 发送它能打开的分区图、对应提示词、总布局、坐标约定和接缝。主 agent 负责接入、跨区路线和共享渲染。用户明确选过且仍适用于该项目的建模模型和推理等级应随交接沿用，例如 GPT-6.2 Astra Ultra；调度时核实可用性。实际没有完成的生图或独立分工，要说明缺口并与用户约定替代方式。
5. **先单灯查几何，再定稿光追。** 用一盏强侧光，沿真实路线从远景走到接缝近景。修正无意的悬空、错台、穿插和错误法线，保留有设计依据的断裂。锁定机位和光源复拍，再用最终网格建立或更新光追数据。见[渲染与验收](references/render-and-test.md)。
6. **交付最终 HTML。** 提供能从磁盘直接打开的 Three.js 单文件，带自由探索、可切换灯光、主灯强度和独立光追开关。在断网浏览器实际打开交付文件，操作相机、灯光和光追。最终回复给出文件、操作方法和所用光追的范围；关键取舍或未验证项要说清。概念图、分区图和源码可以留在制作目录，交付的 HTML 可单独带走。

## 继续改一个场景

从发生变化的环节接着做。换灯时保留机位和原有交互，先记录基线；修几何时复查相关接缝和光追数据。用户要做另一个候选布局时，取出此前保存的候选图与提示词，从该方案的灰模和分区继续。工作目录中优先复用经验证的场景模块、材质、打包器和测试。

## 以后怎样改这套流程

本次项目的要求优先。单个场景的风格、区域数、灯色、模型、设备预算和键位可以单独调整。用户要求长期改进 skill 时，再修改对应环节：选案和生图改美术参考，分工或接缝改交接参考，光追与交付改验收参考；只有流程顺序或默认交付发生变化时才改本入口。用一个能体现这次改动的真实案例复验。
